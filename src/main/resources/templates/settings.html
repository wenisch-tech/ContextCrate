Retrieval

How passages are found for searches and answers.

Proposition retrieval makes two answer-model calls per chunk before embedding and requires both providers. Changing the strategy rebuilds the index in the background.

Only used in fusion mode. Keyword and vector scores are scaled to 0–1 and combined: 0 = keyword only, 0.5 = equal, 1 = vector only.

Contextual chunk headers

The answer model writes a title for every document, and that header is put in front of each chunk before the chunk is embedded and indexed, so a passage keeps its context. Answers and citations still use the original chunk.

The first words of each document are used to write the title (100 to 5,000, default 1,000). One answer-model call per document, cached until the document, the model or these settings change. Those words are sent to the answer provider. Changing the variant or the number of words rebuilds the index in the background. Requires an enabled answer model and embeddings. If a title cannot be created, the document is indexed without a header.

Query transformation

Reshapes the question before retrieval so answers find better passages. The original question is still what the model answers.

Selected strategies run in this order: rewriting → step-back → sub-queries, each building on the previous result. Every active strategy adds one answer-model call before retrieval. Requires an enabled answer model.

Context window

Every chunk found by the search is expanded with the chunks before and after it in its document, so the answer model reads the whole passage instead of a fragment. The chunks are joined in document order and the overlap of the chunking is removed.

0 turns it off. With 1 a match at index 7 is sent together with the chunks at index 6 and 8 (a window of three). Windows of neighbouring matches are merged. Applies to answers only, not to search results, and takes effect immediately without a rebuild. A window makes the answer context larger: raise the answering context budget if sources are cut off.

Context compression

After retrieval, a model reads every retrieved chunk together with the question and keeps only the sentences that matter for the question. Chunks without a relevant sentence are dropped, and sentences that appear twice are removed. The answer model then receives the shorter, denser context.

Best for large chunks, questions about specific details, and models with a small context window. It costs one extra model call per retrieved chunk (run in parallel) and adds latency to every answer. The model only selects existing sentences, so the text stays verbatim. Code chunks are kept as they are. If a call fails, that chunk is used unchanged. Needs the answer model, applies to answers only and takes effect immediately without a rebuild. With the context window, the window is built first and then compressed.

Document enrichment

After chunking, the answer model writes questions that each chunk answers. The questions are embedded and indexed next to the chunk and point back at it. A user question is then compared with questions, which look like it, as well as with passages; when a generated question is the nearest match, the chunk it belongs to is retrieved and used as context. The mirror image of HyDE.

3 to 50, default 5. More questions cover more ways to ask but make ingestion slower and the index larger. Costs one model call per chunk and one embedding per question. Changing this setting rebuilds the index in the background (questions of unchanged chunks with the same count are reused, so only new chunks call the model). If the model cannot be reached, a chunk is indexed without questions and tried again on the next rebuild.

HyDE

Hypothetical Document Embeddings. The answer model first writes a short hypothetical answer; that text, not the question, is embedded for the vector search. Only real chunks are used to answer, and the hypothetical text is discarded.

Helps with short or vague questions whose wording differs from the documents. Costs one answer-model call (about 1,000 characters) per searched query before retrieval, and sends the question to the answer provider. The keyword part of hybrid search, reranking, grading and verification keep using the original question. Skipped in lexical mode, and when embeddings or the answer model are unavailable. Takes effect immediately; no rebuild.

Images

Makes meaningful images in web pages, Markdown and Git repositories searchable and citable. Icons, logos, badges, avatars and tracking pixels are skipped. Applies to the next ingestion run.

When on, an image becomes a searchable reference built from its alt text, caption, file name and the text around it. Turn it off to ignore images completely, including image files in Git. Existing image entries are kept until the documents are ingested again.
