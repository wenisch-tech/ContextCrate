Onboarding policy

Applied only when a new local or OIDC account is first provisioned. Existing users are unchanged.

ADD_TO_EXISTING_CRATE — add new users to a selected crate as Viewers.
SHOW_NEW_CRATE_DIALOG — require the user to create one first crate, even when normal creation policy would deny it.
DO_NOTHING — leave the user on their crate overview.

Model policy

What crate owners may configure themselves. Shared models (see the Models tab) are always selectable. Crates that already use a custom setup keep working; they just can no longer change it.

System prompts

The answer model always follows ContextCrate's built-in rules (grounding, citations, untrusted sources). On top of them you can add an installation-wide prompt, and let crate owners add their own. Each layer is added after the previous one and cannot override it.

Turning this off keeps the prompts crate owners already wrote, but they are no longer applied.

0 / 4000 characters. Applies to every crate, always comes before a crate's own prompt, and is visible to crate owners in their settings. Use it for tone, language or company rules, not for secrets.

Dedicated storage and search

By default every crate uses the storage provider and the search backend of the installation. Allow crate creators to choose their own when they create a crate. The choice is fixed afterwards. Endpoints must not point into private networks unless the crawler allows it.

Without this, a backend with an untrusted certificate is refused. The installation-wide contextcrate.tls.trust-all-certificates setting applies to these backends as well, regardless of this option.

Crate creation

Who may create new crates. Administrators may always create crates, regardless of this setting.

EVERYONE — every signed-in user may create crates.
ADMINS_ONLY — only administrators.
ENTITLED_USERS — administrators plus users with the entitlement granted on the Users tab.

Schedule time zone

Scheduled ingestion jobs use this city-based IANA time zone. Daylight-saving changes follow the selected city.

Shared models

Embedding, reranking and answer models that crate owners can pick by name in their crate's provider settings. The endpoint URL and API key stay on the server: crate owners only ever see the name given here. Models marked available to users appear in every owner's list; others stay hidden. Changing the endpoint, model or vector size of an embedding model re-indexes every crate that uses it.

Active elevations

A global administrator has no access to crate content by default. An elevation grants owner-equivalent access to one crate for 30 minutes and audits every action. Archive, restore, and purge are performed inside the crate once an elevation is active. Deleting a crate needs no elevation: it removes data and exposes none.
